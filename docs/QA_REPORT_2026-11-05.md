other organization receives no results. Browser tests collect uncaught page
errors and fail if any are observed.

1. Webpack had no Tailwind utility processing: it compiled but produced an
   unstyled mobile layout (503 px in a 390 px viewport). Configured the same
   installed Tailwind loader for webpack. Generated CSS now contains utilities;
   no new styling dependency or styling system was introduced.

   causing an ENOENT failure. Excluded test results, browser reports and coverage.

   label, and a public non-member invitation is a valid denial of club access.
   Application safeguards were preserved.

## Limits — not certified by these checks

- **Live Supabase Auth:** six provider browser scenarios remain `fixme`/skipped:
  real signup/verification email, confirm link, recovery, Google OAuth, callback
  replay and identity linking. Their application actions/routes have unit tests,
  but live delivery/provider behavior requires a configured staging project.
- **Physical camera:** manual QR submission and duplicate handling are tested;
  actual camera permissions, video capture and decoding need a camera/device.
- **Default Turbopack build:** blocked here by worker port-binding restrictions,
  including on retry with elevated tool permissions. The successful production
  build and browser tests use the supported webpack engine. This does not prove
  the default Turbopack command works in this environment.
- **Production:** staging/deployment configuration, cloud RLS/auth integration,
  hosted Redis/TLS, email/OAuth delivery and production load are not validated by
  local tests. The smoke server without Supabase configuration correctly reports
  a degraded health check; that test checks safe failure, not cloud availability.

Passing these checks provides evidence for the tested local workflows; it is not
a claim that every possible browser, device, input or production condition works.
